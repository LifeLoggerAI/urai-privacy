## What to Open as a GitHub Issue

Open a GitHub issue for:

- missing governance docs
- policy clarification requests
- adoption questions
- product-repo rollout blockers
- non-sensitive template improvements
- non-sensitive validation errors
- broken links or documentation problems

## What Not to Open Publicly

Do not open public GitHub issues for:

- security vulnerabilities
- exposed credentials
- private user data
- suspected breaches
- biometric exposure
- law enforcement requests
- specific user-rights requests
- sensitive operational incidents

Use the private routes above for sensitive privacy/security contact, and require an acknowledgement before treating a report as received. Never include secrets or unnecessary sensitive personal data in an initial report.
